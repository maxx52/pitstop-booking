# Бот PitStop для MAX

Node.js 24. Отдельный процесс на 127.0.0.1:3174. Меню открывает мини-приложение se14970930_bot, показывает возможности и собирает заявку на расчёт. Бот отвечает на события личного диалога. Заявки и черновики сохраняются в SQLite, отдельно от демонстрационной базы записи.

## Запуск на VDS

Из корня проекта создайте файл `private/max-bot.env` с правами 600. Каталог `private` должен иметь права 700 и находиться вне корня статических файлов Nginx.

```dotenv
MAX_BOT_TOKEN=вставьте_токен_из_MAX
MAX_WEBHOOK_SECRET=случайная_строка_из_букв_и_цифр_не_короче_16_символов
MAX_BOT_DB=/абсолютный/закрытый/путь/max-bot.sqlite
MAX_BOT_PORT=3174
MAX_ADMIN_USER_ID=числовой_ID_получателя_уведомлений
MAX_WEBHOOK_URL=https://pitstop.maxxdev.ru/api/max/webhook
```

Токен вводится только на сервере. Секрет можно создать командой `openssl rand -hex 32`. Проверьте доступ к API MAX с сервера. Если требуется дополнительный корневой сертификат, задайте `NODE_EXTRA_CA_CERTS` с путём к сертификату из официального доверенного источника.

```sh
node --env-file=private/max-bot.env server/max/service.js
```

Для постоянной работы зарегистрируйте эту команду в используемом менеджере процессов с автоматическим перезапуском, рабочим каталогом проекта и отдельным экземпляром процесса.

Добавьте в HTTPS server-блок Nginx для pitstop.maxxdev.ru перед общим прокси приложения:

```nginx
location = /api/max/webhook {
    client_max_body_size 64k;
    proxy_pass http://127.0.0.1:3174;
    proxy_set_header Host $host;
}
```

После запуска процесса и проверки `nginx -t` примените конфигурацию и зарегистрируйте webhook:

```sh
node --env-file=private/max-bot.env server/max/setup.js
```

Проверка в MAX: /start → «Возможности» → «Запросить расчёт» → «Продолжить». Пройдите все пять вопросов. Просмотр последних 100 заявок доступен локальному оператору:

```sh
node --env-file=private/max-bot.env server/max/leads.js
```

Повторная доставка одного события не создаёт повторную заявку. Ответы сохраняются в очереди перед отправкой и повторяются после сетевых ошибок. При обрыве соединения после фактической отправки MAX возможен повтор ответа. Резервируйте SQLite штатными средствами SQLite с учётом WAL. Проверки выполняются командой `npm test`.

При заполнении MAX_ADMIN_USER_ID каждое новое обращение создаёт уведомление оператору с номером заявки и всеми полями. Оператор должен ранее запустить бота. Уведомления хранятся в общей очереди и повторяются после ошибок независимо от доставки другим получателям. Старые заявки автоматически не рассылаются.

## Управление заявками

Владелец MAX_ADMIN_USER_ID видит кнопку «Мои заявки» в главном меню. Команда `/leads` открывает последние пять заявок, кнопка «Ещё заявки» листает более ранние. Карточка показывает данные и кнопки «В работу», «Связался», «Подключён», «Отказ». Статус сохраняется в SQLite. Старые заявки получают статус «Новая». Устаревшие кнопки показывают актуальную карточку, сохраняя более свежий статус. Доступ проверяется для каждой команды.
